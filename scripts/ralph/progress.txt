## Codebase Patterns
- Reference the deleted multi-page site via `git show b5e4821:<path>` for old conventions/copy — e.g. `src/components/header.tsx`, `src/components/footer.tsx`, `src/data/projects.ts` (SVG icon/logo path data), `src/app/globals.css` (`.linear-wipe`/`shine` gradient text).
- Stack is Next.js 16 (App Router) + React 19, not the old repo's Next 14/React 18 — chose current versions to avoid the ~5 high-severity CVEs in Next 14.2.35/postcss (see `npm audit`). Static export still works the same (`output: 'export'` + `images.unoptimized: true` in `next.config.js`).
- `next lint` is removed in Next.js 16. Use `eslint .` directly; `eslint.config.mjs` (flat config) imports `eslint-config-next/core-web-vitals` (subpath export, no `.js` suffix) and requires ESLint 9 (peer dep of `eslint-config-next@16`).
- Raleway loads via `next/font/google` (`--font-raleway` CSS var) in `src/app/layout.tsx`, not a Google Fonts `<link>` tag.
- Design tokens (colors, radii, gradient/shine, selection color) are centralized in `tailwind.config.ts` (theme.extend) and `src/app/globals.css`.
- Next.js 16 auto-generates root `AGENTS.md` + `CLAUDE.md` (`@AGENTS.md` include) on `next dev`/`next build` with version-specific warnings — keep them committed (that's their intended use); project-specific notes were appended below the `@AGENTS.md` line in `CLAUDE.md` rather than replacing it.
- Any module that does `fs`/`path` reads at module scope (e.g. `src/lib/posts.ts`) must never be imported for a runtime export by a `'use client'` component — even an apparently-unused import pulls the whole module (and its `fs` import) into the client bundle and fails the Turbopack build. Keep server-only I/O and client-safe helpers/types in separate files; use `import type` for type-only pieces so they're erased.
- Browser verification recipe (no Playwright/MCP needed): `npm run build`, then `cd out && python3 -m http.server 4321 &`, then `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars --window-size=1000,1400 --virtual-time-budget=4000 --screenshot=/tmp/x.png http://localhost:4321/index.html` and read the PNG. Post pages need the explicit `.html` suffix on this server (`/blog/<slug>.html`).
- Frontmatter `date` values are parsed by YAML into JS `Date` objects, not strings — `src/lib/posts.ts` normalizes them to `YYYY-MM-DD`. Any new date-ish frontmatter field must go through the same normalization or it renders as "Invalid Date".
- Post bodies render via `next-mdx-remote/rsc` in `src/app/blog/[slug]/page.tsx`; prose styling lives in the `mdxComponents` map in `src/components/mdx-components.tsx`, not in the MDX files. `@next/mdx` is intentionally not installed.
- Route params are async in Next 16: `{ params }: { params: Promise<{ slug: string }> }` + `await params`.
- `NEXT_PUBLIC_*` env vars are inlined at **build** time by the static export — they must be set in the build environment (e.g. the GitHub Actions step in US-9), never read at runtime. `.env.example` documents the ones this site needs.
- Interactive browser verification (clicks, form state) without Playwright/MCP: run Chrome with `--headless --remote-debugging-port=9222 --user-data-dir=/tmp/cdp-profile`, open a tab via `PUT http://127.0.0.1:9222/json/new?<url>`, then drive it over the returned `webSocketDebuggerUrl` using `Runtime.evaluate` + `Page.captureScreenshot` (Node 24 ships a global `WebSocket`, no npm deps). Plain `--screenshot` only captures the initial render.
- Internal links must use `next/link` (even root-relative hashes like `/#work`) — `@next/next/no-html-link-for-pages` fails lint on `<a href="/...">`.
- CI/deploy lives in `.github/workflows/deploy.yml` (push to `main`). Any new `NEXT_PUBLIC_*` env var must be added to that workflow's build-step `env:` (sourced from a repo variable) or it ships as `undefined` in the static export. The workflow must never deploy `worker/`.
